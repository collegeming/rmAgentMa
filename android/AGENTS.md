# Repository Guidelines

## Project Structure & Module Organization

ConnectBot is a Gradle Android SSH client project with `oss` and `google` product flavors. The main app lives in `app/`, with Kotlin and Java sources under `app/src/main/java/org/connectbot`. UI code is grouped in `ui/`, data and Room code in `data/`, dependency injection in `di/`, terminal/service code in `service/`, and protocol logic in `transport/`. Native code is in `app/src/main/cpp`, Android resources in `app/src/main/res`, and Room schemas in `app/schemas`. Unit tests are in `app/src/test/kotlin`, instrumentation tests in `app/src/androidTest`, and shared test helpers in `app/src/sharedTest/kotlin`. Translation tooling lives under `translations/` (`translate.py` writes `values-<locale>/strings.xml` through a local Ollama model); the upstream gettext `app/locale/` directory does not exist in this repository or upstream HEAD.

rmAgentMa adds `:agent-core` for JVM agent models, ACP, and remote scanner resources, and `:agent-ui` for reusable Compose agent rendering. App integration lives in `app/src/main/java/org/connectbot/agent` and `ui/screens/agents`. Agent-only foreground connections use `AgentConnectionService`; the upstream terminal backend is retained during SSH migration. Scanner isolation tests live in `agent-core/src/test/python`. Shared Mosh build tasks live in `buildSrc`; they validate official release ZIPs, cache them per module under `build/mosh-downloads`, and publish generated artifacts only after complete verification. Do not use old generated output to bypass a failed download. The normal launch route is the renderer whenever a debug build carries the validated renderer assets; the Compose shell is only the failure fallback, which starts on the host list, states the renderer's failure code with a retry of its own, and holds the Agent chat it still contains — host/Agent selection and a workspace → Agent → session history drawer — behind that entry; host management and SSH terminals are explicit auxiliary routes. The Compose shell receives no new capability: a feature added to the renderer and its bridge is not mirrored into the fallback, which is changed only where the fallback itself is wrong. An open conversation keeps its ACP channel while offering chat and TUI views: the TUI is never embedded, because whether an interactive TUI can share one session ID with the ACP process is unverified, so the pane only states the generated `ShellCommands.start` command and hands it to the terminal route with its confirmation step. The session detail sheet (`AgentSessionDetails.kt`, pure projection plus JVM tests) aggregates plan, file changes, commands, test runs, tool calls and usage from the loaded event window only, says so when earlier history is unloaded, and lists approval records read-only; only the chat stream can respond, and only for the current active-session and event instances. Drawer search runs through `AgentSessionSearch` and labels every hit with the matched field (title, preview or working directory), its snippet, and whether the row was re-read from the remote or is only cached; an unloaded scan page or a failed source marks the search range as possibly incomplete instead of claiming a full history, and the top-bar refresh stays the retry entry. Searching conversation *content* is a separate, remote action: it reads transcripts through `RemoteTranscriptSearch`, but only over files the app first names with one bounded, read-only listing, resolving a session directory under the transcript root found below that conversation's own working directory, so an Agent whose history is a database, a conversation whose directory was not found, a host that answered with a listing problem and a search the remote clock cut short are each reported with their own reason and never as a history without that text, and a hit whose conversation is no longer in the loaded list cannot be opened from there. A message addressed to another conversation goes through `AgentMessageQueue` alone: a REQUEST is sent automatically when that conversation is next opened and idle, a NOTIFY is only shown there as a hint, a message the conversation did not take stays queued with a retry, a message its sender withdrew ends as its own terminal state `withdrawn` instead of pending — never handed over, never counted as delivered, and not pending again after a restart — the queue's own list answers every row it still holds, each with one of those three states, and reading it delivers nothing — and nothing is reported as delivered before the receiving conversation took it. Quoting the open conversation into a new one through `AgentSessionReference` only prefills that input box and never sends anything, and the attention inbox is a read-only projection over the loaded conversation alone, which is the only one whose approvals, questions, failure and running turn this app can honestly report. Agent indexes use an AtomicFile snapshot in `noBackupFilesDir`, not the main Room database; the renderer's draft text is stored the same way, because a draft is the user's own content and stays out of the system backup. Opened-session history is persisted the same protected way: one store per conversation key `(hostId, agent, sessionId)` under `noBackupFilesDir/agent-history` holds the pages it already read, their order, the source version, the continuation cursor and an integrity state, opening a conversation and starting the process both leave those pages in place, and only the user's own clear — the repository's `clearHistory()`, asked for as `history.clear` and never as a side effect of anything else — deletes them. Never discard raw replay events to make an oversized history appear loaded, and never report a history as complete on anything but every page having arrived behind the ordered consumption barrier: a write, read, timeout or disconnect failure keeps the pages and the retry position it already had and states that history is incomplete, with the reason, instead of hiding it or overwriting a complete cache with an empty one. Records that repeat across replay, read-back history and live output merge by their source's stable identity or a defined order, never by equal text. A record whose working directory is missing or not absolute stays listed as one whose directory is unknown, with the reason, so it can be read but never continued and never used to start a new conversation in that group; no directory is guessed and no record is dropped. A restored link is checked against the Agent's own records before any state is claimed: `recovery` is `attached` only when the original session was really found there, `gone` when it is really absent and `unknown` whenever that could not be established, and no reconnect path ever resends the prompt of a turn that was already accepted. A host row carries the authentication it was saved with: `auth_method` is `key` or `password`, a password is stored through the repository's own Keystore-backed storage (`setHostPassword`, reported only as `has_password`) and is never read back, echoed, logged or exported, the key a host uses is reported as its `key_id` and `key_name`, and a host set to password authentication connects with that stored password without asking again. The foreground service's notification states the session it holds — running, opening, disconnected or unknown — and never presents an unverified state as running. Prepare an ACP or ZCode handle, start its unique event consumer, then call load; Ready requires the ordered consumption barrier. Before that handle exists, the session's `cwd` is checked read-only over the same host session (`RemoteWorkingDirectoryCheck`, one bounded directory test per target: the POSIX `[ -d ]` chain, or PowerShell's `Test-Path` on a Windows target): a directory the host cannot use fails as itself, with its own code, without starting an Agent process, without consuming the cached probe verdict and without leaving a half-ready handle, while a host that cannot be reached keeps its own connection error. An Agent process that exits before it is ready names a bounded, control-character-stripped tail of its stderr in the terminal error, instead of reporting a bare EOF. `selectedSession` remains readable on failure while `activeSession` is cleared. Historic permission records must never become live approvals. Remote availability is probed separately from history existence; dsh resume needs independently read history because it has no loadSession, and ZCode uses its own strict JSONL protocol rather than ACP. A host row carries the operating system it holds and, on Windows, the Agent target of that host: the Windows host itself — the literal `windows`, with `native` on such a row meaning the same — or `wsl:<distribution>`. Every remote command of a host is wrapped once at its SSH session, so the probe's replicated launch and the session launch enter the same shell context; a Windows target is entered through that relay (cmd.exe parses only base64, and PowerShell's `-EncodedCommand` decodes the exact text back), its installations are looked up with the Windows `where` command and its directories are tested with PowerShell, and a command that exists only as POSIX text — the Agent launch, the scanner, a remote listing — is refused as that fact instead of being handed to a shell that cannot read it. The absolute executable, version and capabilities a completed probe detected are persisted per host and target in `AgentDetectionStore`; they open a session without a new probe and are never replaced by a guessed path, because an Agent with no detected path fails as not installed rather than launching a hardcoded location. A new conversation is created host first: the Agent picker offers only the chosen host's Agents, the ones its probe found ahead of the rest, and marks the kinds that host's probe ruled out, so no Agent is chosen on a host before that host exists. `PubkeyRepository` wraps private key bytes with `PrivateKeyProtector` at the database boundary; never bypass it to save or export private keys. `AppViewModel` initializes key protection before entering Ready. System backups exclude private keys; explicit user-initiated export remains available. Agent interaction responses require the original active-session and event instances to prevent stale approvals. Saved hosts rediscover a changed address through `AgentAddressRedial`, `AgentHostAddressStore` and `AgentLanSshDiscovery`: after a connection failure, recorded addresses and LAN mDNS `_ssh._tcp` candidates are probed, and a candidate is adopted only when its SSH host key matches `hosts.getKnownHostsForHost(hostId)`. Only direct hosts whose address is an IP literal are eligible; the probe never authenticates, prompts, writes known hosts or blocks the host, and adoption rewrites the address alone, leaving host identity, key associations, trust records and session keys unchanged.

`:host-probe` is an isolated debug-only application (`org.rmagentma.hostprobe`) for the packaged AionUi renderer and synthetic native store. It has no dependency on app, Mosh, SSH, user configuration or credentials. The bridge contract is `renderer/contracts/host-v1.json`; native approvals require a separate Android confirmation. Renderer assets are supplied with `-PRendererAssetsDir=<directory>` and validated against their build manifest before packaging. Missing or changed assets fail the build; never substitute a test page or an earlier bundle. Background service and physical-device behavior require separate validation. `:renderer-host` (`org.rmagentma.rendererhost`) is the Android library that implements that host side — the origin/entry bound bridge with its action whitelist and requestId replay ledger, the asset path handler with its CSP headers, the shared message limits and the attachment upload store — and `:host-probe` and the debug variant of `:app` both depend on it so a single copy of this security code serves both: the product debug build packages the same validated assets only when `-PRendererAssetsDir=<directory>` is passed, starts its non-exported renderer host as the main surface only then and leaves it again with a stable failure code whenever that host cannot serve (assets missing or unreadable, no web message bridge, a failed entry load, a dead render process, an undeclared host) so the shell shows that code with its retry instead of a silent exit, keeps its manual renderer entry next to the chat/TUI switch, answers every renderer route from the product's own repositories — the host identity without secrets, the session index as the renderer's conversation list under ids derived reversibly from `(hostId, agent, sessionId)`, the loaded history window and live events, text sends, the running turn, the live approvals, the live question cards with answers validated against the agent's own schema, the connection challenge a host key confirmation or a credential prompt is waiting on, one older page of history, the session index cache dropped through the repository's own clear entry `terminal.open` or as `terminal.command.start`, which now opens that session's own SSH console with the command and answers `opened` only when the console really started, stating its own code and `attachment.abort`), which the send box's own attach entry uploads a picked file through and which buffer that one upload in this host's own `noBackupFilesDir` directory and write it, only when the The chat stream is the product's own event window: every live frame on `message.stream` is the renderer's own `IResponseMessage` shape — `type` plus `data` — while a history row that `messages.list` or `messages.before` answers carries `content` under that same `type`, and the two shapes are not interchangeable; a conversation row and the runtime state it reports carry what the product really verified instead of a guess — a working directory that is missing or not absolute is flagged with its own reason and its sends are refused as `CWD_MISSING`, and `recovery` names `attached`, `gone` or `unknown`; a question arrives as its own card carrying the fields and schema the agent stated, its answer is accepted only for the pending instance of the open conversation and is validated against that schema, and an event the chat has no row for still arrives as one bounded, control-stripped raw line instead of being dropped, while the turn boundary, the context usage the host publishes through `usage.read` and the resolved interaction rows stay silent because the host reports those itself. Credential challenges are read and answered through the host as well: the payload names the host, the kind and the prompt and never the answer, and an answer is passed to the pending request alone and is neither stored, logged nor echoed. Selecting a listed conversation opens it through the same repository switch the Compose chat uses. The Windows-native target — the Windows `where` lookup, the PowerShell directory check and the Agent launch this build refuses there — is covered by JVM tests and has not been verified on a real device.

## Build, Test, and Development Commands

Use the checked-in Gradle wrapper:

- APK and test APK builds run only in the root GitHub workflow, including `:host-probe:assembleDebug :host-probe:assembleDebugAndroidTest -PRendererAssetsDir=<directory>` and the audited release APK (`:app:assembleOssRelease` with the same directory plus `-PRendererAssetsRelease=true`). Do not run local assemble, package, install or verification targets that indirectly build APKs. Local work is limited to JVM tests, lint, Spotless and non-packaging checks.
- `./gradlew :app:assembleOssDebug` builds the open-source debug APK; `-PciDebug=true` uses the separate `.debug.ci` application ID so runner debug signatures do not require uninstalling a local debug app. Root `.github/workflows/android.yml` builds artifacts and runs standard checks; `platforms;android-37.0` is the official SDK package for compileSdk 37. Never add machine credentials or databases to CI artifacts.
- `./gradlew test` runs local JVM/Robolectric tests.
- `./gradlew connectedAndroidTest` runs device/emulator instrumentation tests.
- `./gradlew connectedOssDebugAndroidTest` and `./gradlew connectedGoogleDebugAndroidTest` run flavor-specific instrumentation tests.
- `./gradlew lint` runs Android lint with `app/lint.xml`.
- `./gradlew spotlessCheck` verifies formatting; `./gradlew spotlessApply` formats supported files.
- `./gradlew check test` runs the standard verification set used before submitting changes. For the isolated probe, `./gradlew :host-probe:check :host-probe:test :host-probe:compileDebugAndroidTestKotlin` checks code and compiles instrumentation without building APKs; this does not replace device execution or real renderer validation.

## Coding Style & Naming Conventions

Target Java 17/JVM 17. Kotlin uses ktlint, including Compose rules; Java under `app/src/main/java/org/connectbot` uses Google Java Format through Spotless. Keep package names lowercase and aligned with existing feature areas. Name Kotlin and Java types in `PascalCase`, functions and properties in `camelCase`, and tests as `*Test`. Prefer existing Compose, Hilt, Room, and repository patterns over new abstractions. Declare Gradle dependency and plugin versions in `gradle/libs.versions.toml` and use version catalog aliases from build scripts. In Jetpack Compose, read UI strings from Android resources with `stringResource()`. Add XML comments directly before new `strings.xml` entries so translators understand the string's purpose and placement. Preserve upstream copyright notices. New rmAgentMa files use the current-year rmAgentMa contributors notice from `spotless/agent-license-header.txt`; do not attribute independently written agent code to an upstream author.

## Testing Guidelines

Add focused tests for behavior changes. Use Robolectric for local UI/ViewModel tests in `app/src/test/kotlin`; use Android instrumentation tests only when device APIs, Hilt runner behavior, or emulator state is required. Keep Compose business logic in ViewModels so it can be covered by local tests where practical. Follow existing Mockito guidance in `README_TESTING.md`: use `org.mockito.Mockito` imports rather than mockito-kotlin. For database changes, update Room schema JSON under `app/schemas` and test migrations when relevant. `OpenSSHContainerTest` exercises a real OpenSSH server in Docker; run it from an Android emulator, not a physical device, with Docker available on the host.

Physical-device E2E requires a reachable SSH channel and an unfrozen device: the app reaches the test SSH server through a loopback port mapped with `adb reverse`, which is dropped when the device reconnects and must be re-created before the run. Wake the screen and keep it on (`adb shell "input keyevent KEYCODE_WAKEUP; wm dismiss-keyguard; svc power stayon true"`), disable doze for the run (`adb shell "dumpsys deviceidle disable"`), and afterwards restore `stay_on_while_plugged_in` to `0` and re-enable doze (`adb shell "dumpsys deviceidle enable"`). A sleeping device freezes the app process and turns a stalled turn into a false timeout. Pass instrumentation arguments as `-e key value` pairs, two tokens per flag; `-e key=value` does not configure the runner. Run device tests with `adb install -r` on APKs signed by the same local-only debug key; never uninstall the app or clear its data, and never copy that keystore or its passwords into the repository, CI artifacts, or logs.

## Commit & Pull Request Guidelines

Commit history uses short imperative subjects, for example `Fix pubkey list item compose lint` or `Add unit tests for importKeyFromText`. Keep the subject at 50 characters or less when practical, add a wrapped body for context, and make each commit a logical unit. Before opening a PR, run `git diff --check`, `./gradlew lint`, and `./gradlew check test`. PRs should describe the change, link related issues, mention test coverage, and include screenshots or screen recordings for visible UI changes.

## Agent-Specific Instructions

Do not overwrite unrelated local changes. Keep edits scoped to the requested behavior, preserve generated schema and translation files unless intentionally updating them, and prefer Gradle tasks over ad hoc build commands. Never block the main UI thread; dispatch IPC, network, disk I/O, and other long-running work off the main thread. In injected classes and ViewModels, use the injected `CoroutineDispatchers` instead of hardcoded `Dispatchers.IO` or similar dispatchers so tests can control execution.
